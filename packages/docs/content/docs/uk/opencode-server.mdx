# OpenCode Server

MittrCraft працює поверх сервера OpenCode. За замовчуванням він сам запускає такий сервер, тож вам нічого робити не доводиться. Ця сторінка потрібна лише тоді, коли ви хочете спрямувати MittrCraft на сервер, який ви вже запускаєте, або керувати тим, що він запускає.

## Як MittrCraft знаходить сервер

Коли MittrCraft стартує, він шукає сервер у такому порядку:

1. повторно використовує сервер, який уже запустив
2. підключається до зовнішнього, якщо ви це налаштували (див. нижче)
3. автоматично виявляє сервер на стандартному порту (`4096`)
4. інакше — запускає й керує власним

Якщо нічого не налаштовано, крок 4 відбувається автоматично, і все працює.

## Підключення до сервера, який ви вже запускаєте

Задайте це перед запуском MittrCraft:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true mittrcraft
```

- `OPENCODE_HOST` — повна адреса вашого сервера OpenCode, разом із портом (значення на кшталт `http://localhost:4096`). У кінці не повинно бути шляху.
- `OPENCODE_SKIP_START=true` — каже MittrCraft не запускати власний сервер.

Якщо вам потрібно лише змінити порт, задайте `OPENCODE_PORT` замість `OPENCODE_HOST`.

Якщо в `OPENCODE_HOST` бракує порту або є шлях, MittrCraft ігнорує його й повертається до запуску власного сервера. Слідкуйте за журналами запуску на предмет попередження `[config]`, якщо очікуване підключення не відбулося.

## Керування сервером із CLI

```bash
mittrcraft status
mittrcraft logs
mittrcraft restart
mittrcraft stop
```

`mittrcraft` сам по собі запускає сервер у фоні. Додайте `--foreground`, щоб лишити його прив'язаним до вашого терміналу.

## Запуск MittrCraft при вході в систему

Скористайтеся `startup enable`, щоб встановити нативний користувацький сервіс. MittrCraft використовує `launchd` на macOS, `systemd --user` на Linux і Task Scheduler на Windows.

```bash
mittrcraft startup enable
mittrcraft startup status
mittrcraft startup disable
```

Щоб захистити UI, задайте пароль під час увімкнення сервісу:

```bash
MITTRCRAFT_UI_PASSWORD='secret' mittrcraft startup enable
```

Для headless-сервера, який стартує під час входу та використовується desktop або mobile застосунками, додайте `--api-only` і доступний host:

```bash
mittrcraft startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` зберігає знімок поточного середовища в сервісі, щоб запуск був ближчим до ручного запуску `mittrcraft` з тієї самої shell-сесії. Так зберігаються токени провайдерів, `PATH`, налаштування SSH agent та інші CLI-змінні для auth/config. Використайте `--no-env-snapshot`, якщо потрібне мінімальне середовище сервісу.

Startup-сервіс пам'ятає `--port`, `--host`, `--ui-password` і `--api-only`. CLI restart і restart під час оновлення повторно використовують ці збережені налаштування.

Щоб створити link підключення для іншого застосунку MittrCraft, використайте:

```bash
mittrcraft connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустіть `mittrcraft connect-url --help`, щоб побачити всі опції link, зокрема `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` і `--qr`.

Тунелями для такого запущеного сервісу можна керувати окремо:

```bash
mittrcraft tunnel start --port 3000
mittrcraft tunnel stop --port 3000
```

Зупинка тунелю не перезапускає сервіс або застосунок.

## «OpenCode перезапускається»

Поки сервер запускається або перезапускається, MittrCraft показує стан «OpenCode перезапускається» і призупиняє запити, доки той не буде готовий. Це нормально одразу після запуску чи перезапуску. Якщо стан так і не зникає, див. [Підключення до OpenCode](/uk/troubleshooting/opencode-connection/).
