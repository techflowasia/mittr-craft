## How the runs were isolated

- Each run had its own temp `HOME` from `mktemp -d "$TMPDIR/g11d.XXXX"` (Dev) or `g11p.XXXX` (prod layout). Both were removed afterwards.
- The app was launched as a direct binary with:

  ```
  env HOME=<temp> OPENCHAMBER_DESKTOP_USER_DATA_DIR=<temp>/userData \
    ".../MittrCraft Dev.app/Contents/MacOS/MittrCraft Dev" &
  ```

  Each test process was quit with `kill -TERM <pid>`, using the PID recorded at launch.
- The installed MittrCraft 1.22 (pid 2848, port 57123, engines 3624 on 58888 and 3635 on 58907) was never signalled, opened or driven.
- Screenshots were taken only of the test app's own window: `screencapture -l <id>`, with the window id from `CGWindowListCopyWindowInfo` filtered by the test PID.
- Session views were also checked in a browser pointed at the test app's own port.

### Copying the data

**Dev:** `cp -Rp ~/.config/mittrcraft-dev <temp>/.config/`.

- The Dev 1.22 app was not running, and `lsof +D ~/.config/mittrcraft-dev` was empty before the copy.
- The `stat` listing (mtime and size of every file) and the `shasum` of every `opencode*.db*` were identical before and after the copy.
- The copy had the same file list and byte-identical db, `-wal` and `-shm` files.

**Prod layout:** the four 1.22 bases were copied into the same paths under the temp HOME:

```
rsync -a --exclude '/speech-models/' --exclude '/managed-opencode/*.json' ~/.config/mittrcraft/ <temp>/.config/mittrcraft/
rsync -a ~/.local/share/mittrcraft/engine/ <temp>/.local/share/mittrcraft/engine/
rsync -a ~/.local/state/mittrcraft/engine/ <temp>/.local/state/mittrcraft/engine/
rsync -a ~/.cache/mittrcraft/engine/       <temp>/.cache/mittrcraft/engine/
```

- **Why two paths were excluded:**
  - `speech-models` is 631 MB of downloadable models, and the backup excludes it anyway.
  - `managed-opencode/*.json` holds the live 1.22 registry entries for pids 3624/3635. Upstream's startup reaper reads that registry. It would leave a live-owned process alone, but there is no reason to hand a test run the owner's live pids.
- **Source unchanged:** the `stat` listing of all four bases was identical before and after the copy.
- **Copy identical:** `cmp` of the 574 MB `opencode.db` and `shasum` of the other db files matched the copy.
- **Database was idle:** the live engines (3624/3635) held the source db, but its last write was 2026-10-15 14:45, so the copy was consistent.

### Prod-layout run

The prod flavor would fall back to a free port on its own: `main.mjs` tries the stored port and then 57123, then calls `pickUnusedPort`. It was still **not built or launched**, because it shares bundle id `dev.mittrcraft.desktop` and the `mittrcraft://` scheme with the installed, running 1.22. A second registered copy with a higher version can take over that bundle id and scheme in LaunchServices.

Instead, the packaged server from the Dev build ran headless with the prod product file:

```
env -i HOME=<temp> PATH=/usr/bin:/bin:/usr/sbin:/sbin USER=… SHELL=/bin/zsh TMPDIR=$TMPDIR ELECTRON_RUN_AS_NODE=1 \
  ".../MittrCraft Dev.app/Contents/MacOS/MittrCraft Dev" <ev>/prod-headless.mjs brand/product.prod.json \
  ".../MittrCraft Dev.app/Contents/Resources" 57143
```

The launcher:

- applies `brand/product.prod.json` `env` with `~` expanded to the temp HOME. That gives `OPENCHAMBER_DATA_DIR=<temp>/.config/mittrcraft` and `OPENCODE_CONFIG_DIR`, and leaves `MITTRCRAFT_ENGINE_HOME` unset;
- creates `ensureDirs`;
- sets `OPENCHAMBER_SERVER_PLUGINS` to the packaged `app.asar/product-plugins/mittr-server.mjs` and `OPENCODE_BINARY` to the bundled engine;
- imports `app.asar/node_modules/@openchamber/web/server/index.js` and calls `startWebUiServer` on port 57143.

So it runs the same server code, the same plugin and the same engine as the app, with the prod data layout.

## R16 — manual step for the owner's real Dev install (not done here)

Before the first start of a 2.x Dev build, check the owner's real Dev settings file. Remove the `desktopLocalPort` line if it holds `57123`:

```
~/.config/mittrcraft-dev/settings.json   →   delete  "desktopLocalPort": 57123
```
